### F-1 — `start` reports the requested port as "the port actually bound" (lens 1 correctness, lens 3 user surface) — `resolved`, severity minor, **untagged** (production-code fix)

- `apps/calc-service/src/server.ts:8` documents `RunningServer.port` as "The port actually bound."; `server.ts:21-24` assigns it `resolvePort(env)` — the requested port — and `server.ts:37` prints that value as `calc-service listening on port ${port}`.
- The two diverge for any request of port `0`: `config.ts:11` resolves `CALC_SERVICE_PORT=` (set but empty) to `Number("") === 0`, as `tdd-3.md` § Observations itself notes, and Node then binds an OS-chosen port while `start` resolves `port: 0` and the entry point announces port 0.
- `@hono/node-server`'s `serve(options, listeningListener?: (info: AddressInfo) => void)` (`node_modules/@hono/node-server/dist/index.d.mts:78`) hands the bound address to the callback `server.ts:22` already registers, so the accurate value costs one argument: resolve `{ port: info.port, ... }` from the listener. That makes the doc comment true and the announcement honest without changing any spec-covered case (`server.test.ts:41` still holds, since with a concrete port the two are equal).
- No criterion demands a test for port `0`; the fix is the code. If the fix step wants a pin, a `start({ CALC_SERVICE_PORT: "0" })` case asserting `running.port !== 0` and a `200` on `running.port` would do, but it is not required to close this finding.
- **Resolution** (fix step, TDD): RED `src/server.test.ts` › start › "reports the port actually bound, not the one requested, when the OS picks it" — `start({ CALC_SERVICE_PORT: "0" })`, `running.port` not `0`, `POST /calculate` on `running.port` → `200 { result: 5 }`; failed with `expected +0 not to be +0`. GREEN `server.ts`: `serve({ …, port: resolvePort(env) }, (info) => resolve({ port: info.port, … }))` — the `AddressInfo` the listener receives is the bound address, so `RunningServer.port` and the `listening on port` line now carry it; the doc comment names the `0` case. Verification 12/12, exit 0.
